# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 35-37) | **Incorrect late boundary condition and whole-minute truncation bug (R2):** The check `minutes > 10` is performed on floored minutes. For a 09:30 shift, punching in at 09:40:01 yields 10 minutes and 1 second, where `int(total_seconds / 60)` evaluates to 10. Because `10 > 10` is `False`, the function erroneously returns 0 instead of 10. | Test punch-in at 09:40:01 for a 09:30 shift; expected 10 late minutes, but function returned 0. | Calculated total elapsed seconds between punch-in and shift start in IST. Checked `seconds_elapsed > 600` (strictly more than 10 minutes grace per R2). If true, returned `int(seconds_elapsed // 60)` (floor minutes elapsed since shift start). |
| 2 | `compute_late_minutes` (lines 34-36) | **Timezone and overnight shift blindness (R1):** Naively constructs `start` by replacing hour and minute on `punch_in` without accounting for IST conversion or overnight shifts. For an overnight shift (e.g. 22:00 - 06:00) where punch-in is at 01:00 IST next day, `replace(hour=22)` sets `start` 21 hours in the future, resulting in negative elapsed time. | Test punch-in at 00:30 IST on an overnight shift starting at 22:00 IST; returns 0 late minutes instead of 150. | Computed `attendance_date` with overnight shift logic (R1), aligned `shift_start` to that specific attendance date in IST (`UTC+05:30`), and calculated positive duration elapsed. |
| 3 | `compute_work_hours` (line 41) | **Banker's rounding violation (R4):** Uses Python's built-in `round()`, which performs round-half-to-even (banker's rounding) on floats instead of standard half-up rounding. For example, 2.525 rounds to 2.52 instead of 2.53. | Test punch duration yielding 2.525 hours; `round()` produces 2.52, violating rule R4 ("rounded to 2 decimals half-up (not banker's rounding, not float rounding)"). | Implemented `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)` from the Python standard library `decimal` module. |
| 4 | `compute_overtime` (line 47) | **Missing 30-minute qualification threshold (R3):** Uses `max(0, int((punch_out - end).total_seconds() / 60))` without enforcing the minimum 30-minute threshold required by R3. Overtime under 30 minutes (e.g. 15 minutes) is improperly awarded. | Test punch-out at 18:45 for an 18:30 shift end (15 minutes overtime); function returns 15 instead of 0. | Added condition checking `if elapsed_minutes >= 30: return elapsed_minutes else: return 0`. |
| 5 | `compute_overtime` (lines 45-47) | **Overnight shift end date calculation error (R1, R3):** Assumes `shift_end` is on `date_str`. For overnight shifts (e.g. 22:00 - 06:00 on 2026-07-06), `shift_end` is on the next calendar day (2026-07-07 06:00). Setting `shift_end` on `date_str` sets it 16 hours in the past. | Test overnight shift punch-out at 06:40 IST on the day following shift start; computes ~980 minutes of overtime instead of 40. | When `shift_end <= shift_start`, set `shift_end` datetime to `attendance_date + 1 day` at `shift_end` time in IST. |
| 6 | `/health` (lines 72-74) | **Unconditional health status without database ping:** Returns `{"status": "ok"}` without testing connectivity to MongoDB. The contract states: "Returns 200 only if MongoDB answers a ping, otherwise 503." | Stop MongoDB or supply an invalid `MONGO_URI`; `GET /health` returns 200 OK instead of 503 Service Unavailable. | Wrapped `client.admin.command("ping")` in a try/except block; returns 200 on success and raises `HTTPException(503, "Database unavailable")` on failure. |
| 7 | `create_employee` (lines 79-83) | **Check-then-insert race condition on unique identifier:** Checks `find_one({"emp_code": body.emp_code})` before `insert_one()`. Concurrent requests with the same `emp_code` will both pass the check and create duplicate documents. | Send concurrent identical `POST /employees` requests; both return 201 Created and corrupt the collection. | Created a unique index on `emp_code` in MongoDB at startup (`db.employees.create_index([("emp_code", 1)], unique=True)`), and handled `DuplicateKeyError` to return HTTP 409 Conflict. |
| 8 | `create_employee` (lines 81-85) | **Invalid response schema and unvalidated input fields:** Stores and returns `created_at` as a Python `datetime` (serializing to an ISO string) instead of integer epoch milliseconds per OpenAPI `EpochMillis`. Also fails to validate that `shift_start != shift_end`, email pattern/length, or employee code regex (`^EMP\d{4,6}$`). | POST an employee with `shift_start: "09:30", shift_end: "09:30"`; starter returns 201 instead of 422. Response `created_at` is an ISO string instead of integer epoch milliseconds. | Implemented Pydantic model validations for regex patterns and `shift_start != shift_end`. Formatted `created_at` as epoch milliseconds integer. |
| 9 | `list_employees` (lines 89-96) | **Off-by-one page calculation skipping the first page (R10):** Uses `skip = page * page_size`. Since `page` is 1-indexed (page >= 1), page 1 skips `1 * 20 = 20` documents, omitting the first 20 employees entirely. | Query `GET /employees?page=1`; returns records 21-40, omitting the first page. | Changed pagination skip formula to `skip = (page - 1) * page_size`. |
| 10 | `list_employees` (lines 94-96) | **Unfiltered total count and missing sort:** `total` runs `db.employees.count_documents({})`, counting all employees rather than the filtered subset. Also does not sort by `emp_code` ascending as required by the contract. | Filter `GET /employees?department=Engineering`; `total` returns entire company headcount instead of department count. | Calculated `total = db.employees.count_documents(q)` and added `.sort([("emp_code", ASCENDING)])`. |
| 11 | `punch_in` (lines 101, 113) | **Unhandled missing employee error leading to 500:** Accesses `emp["shift_start"]` without checking if `emp` was found. If an unknown `emp_code` is submitted, `emp` is `None`, raising an unhandled `TypeError`. | Send `POST /attendance/punch-in` with non-existent `emp_code: "EMP9999"`; returns 500 Internal Server Error instead of 404 Not Found. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 12 | `punch_in` (lines 104-118) | **Punch-in concurrency race condition:** Relies on `db.attendance_logs.find_one` before `insert_one`. Simultaneous punch-ins for the same employee on the same date will both pass the check and create duplicate records. | Send simultaneous punch-in requests for the same employee and date; both return 201 Created. | Enforced database unique compound index on `("emp_code", "date")` and caught `DuplicateKeyError` to return HTTP 409 Conflict. |
| 13 | `punch_in` (lines 102-108) | **Date derivation ignores IST and overnight shifts (R1):** Uses `ts.date().isoformat()` from local system time instead of IST calendar date. Fails to assign overnight shift punches before `shift_end` to the previous calendar day. Does not truncate instants to whole seconds. | Punch in at 00:30 IST on an overnight shift (22:00 - 06:00); record is assigned current date instead of shift start date. | Implemented `determine_attendance_date` with whole second truncation, IST conversion, and overnight shift calendar date rollback. |
| 14 | `punch_in` (lines 119-121) | **Contract violation returning internal `id`:** Attaches `doc["id"] = str(res.inserted_id)`. The specification explicitly forbids exposing MongoDB's internal `_id` or an `id` field in attendance records. | Validate response against OpenAPI `AttendanceRecord` schema; schema validation fails due to extra `id` field and unconverted datetime `punch_in`. | Removed `id` field and serialized `punch_in` to epoch milliseconds integer. |
| 15 | `punch_in` (lines 63-67) | **Unvalidated request parameters:** Accepts any arbitrary status string (e.g. `"LEAVE"`, `"ABSENT"`, `"INVALID"`) and out-of-range timestamps (< 100000000000). | POST `/attendance/punch-in` with `status: "LEAVE"` or `punched_at: 1700000000`; returns 201 instead of 422. | Restricted `status` to `PresenceStatus` enum (`PRESENT`, `WFH`, `ON_DUTY`) and validated `punched_at` against `EpochMillis` bounds. |
| 16 | `list_attendance` (lines 144-150) | **Memory exhaustion and in-memory sorting failure:** Loads the entire collection into Python memory using `list(db.attendance_logs.find(q))` and sorts in Python. Fails on ~100k documents. Missing secondary sort by `emp_code` ascending. Missing date range validation (`date_from > date_to`). | Query `/attendance` with 100k documents in MongoDB; causes massive memory spike and timeout. Call with `date_from="2026-07-10"&date_to="2026-07-01"`; returns 200 instead of 422. | Pushed pagination and sorting `[("date", DESCENDING), ("emp_code", ASCENDING)]` directly to MongoDB cursor backed by compound index. Added validation `if date_from > date_to: raise 422`. Formatted items into `AttendanceRecord` schema. |

## Items examined and confirmed NOT to be defects

1. **`load_dotenv(override=False)`**: Loading local `.env` is appropriate for developer convenience as long as environment variables set by the host/grader take precedence. Using `override=False` ensures system environment variables always take priority over `.env`.
2. **Default shift times `09:30` and `18:30` on `EmployeeCreate`**: Matches the exact defaults specified in `openapi.yaml`.
3. **Absence of `id` on Attendance Records**: Addressing records naturally by `(emp_code, date)` without exposing an artificial ID aligns directly with the assignment data model.
